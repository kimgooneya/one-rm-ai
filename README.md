# one-rm-ai · 리프트 노트 / Lift Note

React 웹 경험에서 이어갈 수 있는 **React Native + Expo + TypeScript** iOS/Android 초기 프로토타입입니다. 서버·계정·배포 없이 로컬에서 실행하며, 처음에는 빈 공책입니다. 개인 운동 기록이나 샘플 훈련 처방은 포함하지 않습니다.

## 실행

Node.js **22.18+ 또는 24 LTS**, npm을 사용하세요. Node의 TypeScript 실행 기능으로 테스트를 돌립니다.

```sh
npm ci
npm run check
npx expo install --check
npm start
```

- iOS: SDK 58을 지원하는 Expo Go 또는 로컬 development build. 시뮬레이터/네이티브 빌드에는 macOS + Xcode가 필요합니다.
- Android: SDK 58을 지원하는 Expo Go 또는 로컬 development build / Android Studio.
- SDK 58 발표문에는 스토어 Expo Go 배포가 늦을 수 있다고 명시되어 있습니다. 실행 시 설치된 Expo Go의 SDK 지원을 확인하세요. 스토어 앱과 맞지 않으면 development build가 필요합니다.
- 웹은 이번 범위가 아닙니다. SQLite 네이티브 경로를 구현했습니다.
- 빌드 계정·EAS 프로젝트·앱 ID·서명·배포는 설정하지 않았습니다.

## 구현한 것

- 한국어 다크 UI, 운동일 / 기록·주간 화면, 키보드 입력·안전 영역 대응.
- 종목 → 중량 → 목표 세트 수 → 횟수로 계획 입력. 목표 수만큼 개별 세트 생성.
- 세트별 수행 체크, 수정, 확인 후 삭제. 전체 및 종목별 **수행 / 목표** 집계.
- 세션 공통 목표 RPE (`@6` = 목표 6), 선택적인 개별 실제 RPE. 1~10, 0.5 단위.
- 컨디션 하나의 점수: 1 매우 나쁨 ~ 5 매우 좋음. 선택을 다시 누르면 미입력으로 변경.
- 수동 블록/주차/운동일 이름. 날짜를 지정해 과거 수정·미래 계획 가능.
- 지난주(월~일) 계획을 이번 주로 복사. 원래 계획 중량/횟수 및 공통 목표는 보존하고 수행 체크·실제 RPE·컨디션·주차 이름은 초기화. 대상 날짜 하나라도 이미 있으면 **전체 복사를 거절**해 기존 데이터를 보호합니다.
- 완료된 작업 세트만 `kg × 실제 횟수`로 볼륨 계산. 미수행/워밍업 제외. 실제 RPE 미입력은 평균의 0으로 처리하지 않습니다.
- SQLite 기반 `expo-sqlite/kv-store`에 버전 포함 JSON 한 문서로 저장. 저장 성공 후에만 UI 반영. 읽기/검증 오류 시 기존 데이터 덮어쓰기 방지.
- 저장 중 중복 제출/입력 잠금, 날짜 변경 시 미저장 입력 폐기 확인.

### 계획과 실제 기록

계획 세트를 추가하면 미수행 상태입니다. 완료 체크는 표시된 중량/횟수를 실제로 수행했다는 확인입니다. 완료 후 **수정**하면 실제 중량/횟수/RPE를 바꿀 수 있으며 처음 계획 중량/횟수는 보존합니다. 미완료 세트 수정은 계획도 수정합니다. 실패/0회 시도 기록은 아직 지원하지 않습니다. 수행 체크 해제는 볼륨에서 제외하며 입력값은 남깁니다.

기록일은 화면에 표시된 선택 날짜이며 자정에 자동 전환하지 않습니다. **오늘 날짜로 이동**을 눌러 새 운동일을 열 수 있습니다. 주간 요약은 기기 현지 날짜 기준 이번 주 월요일부터 오늘까지입니다.

## 파일 구조

- `App.tsx`: UI, 입력 상태, 확인 대화상자, 저장 오케스트레이션
- `src/domain.ts`: 데이터 타입, 검증, 실제 볼륨/RPE 집계, 완료 설정, 안전한 주간 복사
- `src/storage.ts`: SQLite key/value 저장 어댑터
- `tests/domain.test.mjs`: Node 내장 테스트 (외부 테스트 서비스 없음)
- `package-lock.json`: 고정 의존성 트리

## 기록 형식

종목 / 중량 / 목표 세트 수 / 횟수 순서. 목표 세트 옆 正 표시는 수행 세트 수입니다(실패 표시나 RPE가 아님). RPE 목표는 당일 공통이며 컨디션은 한 점수입니다. 개인 기록 데이터는 포함하지 않습니다.

## 이번 프로토타입의 한계

- 한 날짜에 세션 하나, kg만. 3대 운동 단축 선택과 보조 운동 이름 직접 입력을 지원합니다. 단위 전환·하루 여러 세션은 후속 작업입니다.
- 세트 삭제는 해당 계획도 제거합니다. 계획 보존이 필요하면 완료를 해제하세요.
- 훈련 블록 자동 생성, 자동 증량, 권장 강도, e1RM 처방 없음.
- SQLite는 암호화하지 않았고 클라우드 동기화/내보내기/백업/복구 UI는 없습니다. **앱 삭제나 기기 분실 시 데이터가 사라질 수 있으므로 실제 주 기록장 대체 전에 백업을 구현해야 합니다.**
- 미저장 폼은 앱 종료 시 복구하지 않습니다. `메모 저장` 및 `계획 세트 추가`/수정/완료 체크 성공 표시를 확인하세요.
- JSON 문서 저장은 작은 개인 로그용 시작점입니다. 기록 규모가 커지면 정규화된 SQLite 테이블과 마이그레이션으로 분리하세요.
